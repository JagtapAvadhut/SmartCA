## BUG-0002

| Field | Value |
|-------|--------|
| **Title** | Manager can execute TL Verify and CA Verify — breaks review segregation of duties |
| **Severity** | Critical |
| **Priority** | P0 |
| **Status** | **FIXED-PENDING-QA** |
| **Steps** | 1. Login Manager. 2. List `status=READY_FOR_TL_VERIFY`. 3. `POST /items/{id}/verify/tl` `{decision:"pass"}`. 4. Immediately `POST /items/{id}/verify/ca` `{decision:"pass"}`. |
| **Expected** | Only TL (verify.tl) and CA (verify.ca) may pass those gates. Manager may close at end of chain, not perform TL/CA verify. |
| **Actual (original)** | Both calls return **200**. Manager alone advances `READY_FOR_TL_VERIFY` → `READY_FOR_CA_VERIFY` → `READY_FOR_MANAGER_CLOSE`. |
| **Screenshot** | N/A |
| **Video** | N/A |
| **API evidence (original)** | Work `019fa328-f695-796b-889f-4f107a83087b`: mgr TL verify 200; mgr CA verify 200. |
| **Database evidence (original)** | `wm_work_transitions` actor_id `WM-MGR-0001` on `verify_tl` / `verify_ca` actions (partner-gate works also show mgr as closer). |
| **Root Cause hypothesis** | Manager role granted `AllPermissions()` including `work.verify.tl` and `work.verify.ca`. Middleware accepts hierarchy-derived grants. |
| **Fix (Developer)** | Strip `work.verify.tl` / `work.verify.ca` from Manager defaults; hard-deny Manager on `VerifyTL`/`VerifyCA`; reject CA verify when actor is the same as the TL-pass verifier. Regression: `TestVerifyGates_SoD_ManagerAndSameActorCannotBoth`. |
