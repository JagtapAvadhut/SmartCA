## BUG-0001

| Field | Value |
|-------|--------|
| **Title** | `requiresPartnerSignoff` / partner-required close does not block Manager |
| **Severity** | Critical |
| **Priority** | P0 |
| **Status** | **VERIFIED** (2026-07-27 QA Regression) |
| **Steps** | 1. Login `manager1@wm.smartca.in` / `SmartCA@2025`. 2. `POST /api/v1/work/items` with `riskClass:"high"`, `requiresPartnerSignoff:true`, corporate GSTR fields + assignee. 3. Transition → TL verify → CA verify to `READY_FOR_MANAGER_CLOSE`. 4. As Manager `POST /items/{id}/close`. 5. As Partner attempt close. |
| **Expected** | When `requiresPartnerSignoff` is true, only Partner may close (Architecture: flag forces Partner). Manager must receive 403. |
| **Actual (original)** | Manager close returns **200** and status `CLOSED`. Partner close then **409** (already closed). DB: `requires_partner_signoff=t`, `risk_class=high`, `status=CLOSED` by `WM-MGR-0001`. |
| **Screenshot** | N/A (API) |
| **Video** | N/A |
| **API evidence (original)** | `mgrClose 200` then `partnerClose 409 CONFLICT "close requires READY_FOR_MANAGER_CLOSE or DELIVERED"`. Work ids e.g. `019fa382-dbfd-7a0a-b1af-c784e440ed7b`. |
| **Database evidence (original)** | `SELECT id,status,risk_class,requires_partner_signoff FROM wm_work_items WHERE requires_partner_signoff AND status='CLOSED'` → rows closed by manager. |
| **Root Cause hypothesis** | `CloseWork` treated Manager as allowed when partner flag set (`role != Partner && role != Manager`). Also `PermissionsForRole(manager)` returned `AllPermissions()` including `work.close.partner`. |
| **Fix (Developer)** | `CloseWork` allows only `RolePartner` when `requiresPartnerSignoff`; Manager no longer receives `work.close.partner`. Regression: `TestCloseWork_RequiresPartnerSignoff_BlocksManager`. |
